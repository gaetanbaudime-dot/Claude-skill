VERDICT
Le relais des codes e-mail peut être fiabilisé sans récupérer de secret 2FA.
Les correctifs ci-joints passent 107 tests synthétiques, dont les menus avec
la vraie bibliothèque discord.py 2.7.1, sans connexion Discord ni Gmail.
Cela ne prouve pas encore le parcours réel Instagram → iCloud → Gmail → Discord.
Une application d'authentification/SMS/WhatsApp et un recours Meta demandent
un parcours distinct ; aucune autonomie totale n'est promise.

AUCUNE MODIFICATION DE PERMISSION N'EST NÉCESSAIRE AU PARCOURS PROPOSÉ
Le patch ne crée pas de salon, ne remplace pas ses permissions et ne parcourt ni
supprime son historique. Il ajoute un panneau si nécessaire dans le salon existant.
Le salon commun et le salon perso portent uniquement des boutons sans code : chaque
clic résout les droits de l'UID Discord qui clique et répond en privé.
Si le salon manque ou si le bot n'a pas le droit d'y poster, l'administrateur devra
valider la création ou le changement précis de permission, après lecture des droits.
Aucune correction de permission concrète ne peut être recommandée sans cette lecture.
Les anciens messages éventuellement porteurs de codes ne sont ni lus ni supprimés
par ce patch ; leur présence réelle reste inconnue.

DÉFAUTS CORRIGÉS
- Le dernier code était choisi parmi tous les types/comptes admissibles.
  Le choix privé impose maintenant un usage et un seul alias appartenant à l'UID.
- Les commandes explicites pouvaient perdre leurs arguments lors de leur
  détection en langage naturel. !code connexion conserve maintenant son usage.
- Une date absente/invalide devenait « maintenant ». Elle est désormais refusée ;
  les dates sans fuseau et trop futures ne sont pas servies.
- Un nouveau clic pouvait reprendre le texte du guet précédent, même après un
  changement de compte. Il remplace le guet et revalide ses droits.
- Les anciens accès conservés dans une fiche pouvaient réautoriser un compte retiré.
  Les comptes actuels et les comptes effectivement livrés du deuxième téléphone
  sont distingués ; une fiche révoquée ne récupère pas ses alias historiques.
- Une modification locale des fichiers de propriété invalide le cache UID.
  Un e-mail partagé entre clippers/comptes, ou un compte à adresses contradictoires,
  est refusé. Un e-mail adressé à plusieurs alias n'est pas attribué arbitrairement.
- L'envoi automatique est conservé en DM : un OTP e-mail frais est livré au seul
  propriétaire identifié sans ambiguïté. Le salon perso reçoit une notification
  et des boutons, sans code ni compte. MP fermés : le bouton répond en éphémère.
- Trois boutons persistants correspondent aux trois usages. Un compte lié : un clic
  suffit ; plusieurs comptes : un seul sélecteur privé supplémentaire.
  L'ancien bouton « Mon code » reste fonctionnel après redémarrage.
- La propriété locale refuse aussi deux comptes utilisant le même alias, un compte
  lié à deux UID et les adresses contradictoires d'un même compte.
- L'échec de l'accusé de réception éphémère empêche toute édition potentiellement publique.
- Les exceptions transport ne recopient plus leur contenu dans les journaux/alertes.
  Les clés sans Message-ID sont des empreintes et ne contiennent plus le sujet/code.
- Les raccourcis de classification contrôlent les mutations sensibles dans toutes
  les parties du message. « address » n'est plus pris pour « add ».
- À date égale, la recherche directe numérote du plus ancien au plus récent.
- Les codes e-mail restent uniquement en mémoire ; l'état persistant ne stocke plus
  leurs valeurs. Le cache d'une ancienne politique est invalidé.
- Le mode historique sans filtre ne peut plus être activé par CODES_SECURITES=0.
  Les commandes de restitution ne proposent plus de repli global, y compris au staff.
  Aucun paramètre de sécurité réel n'a été changé pendant cet audit.
- discord.py minimal passe à 2.4 : DynamicItem utilisé par le bouton n'existe pas en 2.3.

CE QUE FAIT UN CLIPPER APRÈS DÉPLOIEMENT
1. Il demande un nouveau code dans Instagram. Le bot livre automatiquement l'OTP
   e-mail de moins de deux minutes par DM si la fiche établit un propriétaire unique.
   Le message indique le compte, l'adresse et l'usage ; le clipper copie le code.
2. En cas de DM fermé ou pour attendre le prochain code : dans son salon perso ou
   « code - Instagram », il clique Créer un compte / Me connecter / Vérifier mon e-mail.
   Un seul compte lié : réponse directe privée. Plusieurs : il choisit le compte dans
   le menu privé. Les boutons ne révèlent ni code ni adresse aux autres membres.
3. Le bot cherche le bon usage sur le seul alias choisi et guette cinq minutes.
   Un renvoi depuis Instagram remplace le code dans la réponse privée en cours.
   Une nouvelle demande interactive ne rejoue pas un code déjà montré par une demande
   précédente. Le DM automatique reste accessible directement dans la conversation.
4. !code reste utilisable depuis les salons et les DM. !code connexion donne directement
   le résultat en DM si un seul compte est lié ; sinon le choix reste privé.
5. Aucun code arrivé : vérifier l'adresse et l'usage, puis demander un renvoi Instagram.
   Ne publier aucun code ni capture non masquée dans un salon.

DISTINCTIONS
Création : code e-mail de confirmation d'inscription, choix « Créer un compte ».
Connexion : code e-mail de connexion, choix « Me connecter ».
Vérification e-mail : modèle de confirmation sur l'adresse déjà associée ; choix
« Vérifier mon e-mail Instagram ». Ce code ne réalise aucun recours et ne remplace
pas une preuve d'identité. L'option existante CODES_VERIFICATION reste respectée.
2FA : TOTP/application d'authentification, SMS ou WhatsApp ne proviennent pas du
relais Gmail. Le titulaire utilise son moyen autorisé directement dans Instagram.
Récupération/codes de secours/changements de sécurité : non distribués par le bot.
Ils nécessitent le parcours officiel et l'autorisation appropriée du titulaire.

RECOURS OFFICIEL META — PARCOURS SIMPLE
1. Ouvrir le compte concerné dans Instagram officiel et lire la notification.
   Noter le motif exact, la date, le statut et le délai affiché. Ne pas inventer
   une cause ni appliquer un délai universel provenant d'un autre produit Meta.
2. Si « Contester » ou « Demander un examen » est proposé, préparer une explication
   factuelle courte et les éléments demandés. Si « En cours d'examen », suivre le
   dossier existant ; ne pas prétendre qu'un nouvel envoi accélérera la décision.
3. Le clipper peut préparer les faits dans son mandat. Si Meta exige le titulaire,
   son selfie vidéo, sa pièce d'identité ou une validation personnelle, le titulaire
   agit lui-même directement dans Meta. Ne jamais substituer une identité ou une
   photo. Ne pas envoyer ces éléments dans Discord ou à l'assistant.
4. Conserver la référence du dossier et le statut, sans secrets. Ne promettre aucun
   délai ni rétablissement. Les options peuvent varier selon le compte et le pays.
5. Pour un compte piraté ou un moyen d'accès perdu, partir du parcours officiel
   Instagram « hacked » ou du centre d'aide depuis l'app. Cela peut nécessiter
   l'intervention personnelle du titulaire. Aucun contournement ni compte de
   remplacement destiné à éviter une suspension.

LIMITES À CONNAÎTRE
La correspondance d'un format e-mail ne prouve pas la réussite d'une connexion Meta.
Le contrôle cryptographique des relais iCloud reste celui du projet existant :
CODES_PREUVE_RELAIS a pour défaut « observer » dans le source. La configuration réelle
et les en-têtes d'un vrai message n'ont pas été lus. Ne pas affirmer que la signature
Meta est vérifiée en production ; une validation des en-têtes, sans contenu ni code,
est nécessaire avant tout éventuel durcissement de ce paramètre.
Le cache issu du Sheet expire après environ sept minutes et est invalidé par les
mutations locales de propriété. Une réattribution faite uniquement dans un Sheet,
non encore synchronisée localement, doit attendre cette synchronisation/expiration.
